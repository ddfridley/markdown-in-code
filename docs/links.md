# Links and references

Approved in F5 and screenshot review on October 20, 2026. All 23 images from run 1792520725803 are accepted, including the two link cases; earlier pending-review notes below are historical. Ctrl+click, local-file return and the floating two-second opened hint have user confirmation. Tables follow this slice; embedded HTML comments come afterward.

In all supported comment forms, including same-line block comments and lone/trailing line comments, Markdown links show an underlined, theme-colored label. Their surrounding brackets, destination and optional title are hidden visually. Bold, italic and inline-code formatting inside labels retains its existing behavior. Angle-bracket autolinks and email links hide their angle brackets; GFM bare URLs/email addresses retain their readable text and gain link styling. Unframed comments retain their comment delimiters.

Full, collapsed and shortcut reference links resolve definitions within the same extracted comment. Identifiers follow the parser's Markdown normalization and case-insensitive matching; the first definition wins. Definitions stay visible so destinations remain inspectable; the destination itself is a styled native link and uses the same cursor-preserving activation. Unresolved references stay literal. Source whitespace, escapes and entities retain the editor's source-based layout rather than HTML text normalization.

Hover a rendered label to inspect its destination and optional title. Clicking still reveals the complete comment for editing. To open a link, place the cursor anywhere inside its source syntax, press Ctrl+Shift+P, and run **Markdown in Code: Open Link at Cursor**. This command works with rendered mode toggled off too. It opens HTTP/HTTPS links and mail addresses externally; relative paths and file URIs open in VS Code. Relative paths resolve from the source file's directory, not the workspace root. Protocol-relative `//example.com` targets use HTTPS. Fragment-only heading navigation and other URI schemes are not implemented by this command. File fragments are passed through to VS Code; Markdown heading lookup is not provided.

Ctrl+click a label to open it through VS Code's native document-link navigation. The activated comment is explicitly left rendered across passive selection and application-focus changes; this no longer depends solely on restoring the source cursor. Use the modifier shown in VS Code's hover if your platform/settings use a different one. A new ordinary focused click, keyboard/command navigation, edit or toggle releases this protection. Native navigation is available in rendered and raw modes; unsupported targets have no extension-provided document link. Rendering and hovering alone never open a target or modify source. Open Link at Cursor remains an alternative command without this native-click presentation policy.

VS Code moves the cursor before reporting native link activation, and its public selection event does not include modifier keys. Mouse clicks inside link labels therefore wait up to 200 ms before revealing source. Native activation cancels that reveal, restores the prior selection when available, and preserves the comment's rendered presentation. A short same-gesture/focus-return grace period protects late callbacks; ordinary focused clicks subsequently reveal source after the usual delay. Keyboard selection and selections outside links retain normal behavior.

Focus, theme and layout refreshes honor that pending click's original presentation selections as well, preventing them from briefly revealing source before native activation arrives. The native mouse suite observes every presentation update during its 33 activations to detect transient source reveal. Activation delayed beyond the 200 ms ordinary-click timeout can still reveal source before recovering; the public API does not expose the modifier needed to distinguish those clicks immediately.

Delayed activation retains the originating click beyond the reveal timer, provided the source version, destination and cursor still match. Cursor history is updated by selection events, not incidental theme/focus/layout refreshes. Native links cover the complete Markdown syntax, including hidden destinations, plus one neighbouring source column within each line. That small hit margin accounts for Monaco mapping a click on the first rendered glyph to the preceding source column. It also prevents hidden destination URLs from using a competing built-in handler. Confirmation prompts remain controlled by the user's VS Code trusted-domain preferences. Destination-capture tests do not launch browser/mail apps or exercise their focus changes.

VS Code's native underline can extend into that one-column hit margin. This is visible in the review images. Native Ctrl+click deliberately leaves its comment rendered even when it was previously revealed; this supersedes the earlier best-effort preserve-prior-edit-mode policy. Explicit source navigation or editing reveals it again. Protection is scoped to the activated comment, editor and document version; it does not apply to another split or other selected comments.

Fenced/indented code, HTML and image syntax retain their existing literal behavior. Image presentation belongs to a later slice. Newlines and hidden long destinations retain the known source-layout and wrapping limitations.

Returning from a local-file link preserves the source comment's rendered state even when VS Code replaces its editor instance. The navigation state transfers only within the same editor group and document version; another split remains independent. Editing a document also invalidates navigation state retained by its hidden tabs.

The native suite now opens the local fixture for real and returns to the source tab before checking ordinary click-to-edit. This round trip and the existing 33 external destination-capture checks pass on both VS Code 1.100.3 and installed 1.142.0. Run GUI suites sequentially so their windows do not compete for mouse focus. Validation also passes all 98 unit tests and 21 integration checks. Accepted screenshot files are unchanged.

External links use the public `vscode.env.openExternal` API. It has no browser foreground/focus option: Windows and the configured browser determine whether the opened page appears in front of Code. The extension does not change those settings or force browser focus.

After a successful external open, a temporary hint above the source link shows the destination followed by `opened` for two seconds. It uses the theme's hover colors and does not move focus or change source. This is an absolutely positioned editor annotation rather than a mouse-position popup: it overlays the preceding line without pushing text sideways. It ignores mouse input and truncates very long destinations. Near the top of the editor it may be clipped. Canceled or failed opens do not show success; a newer confirmation replaces the previous one. Local-file navigation opens its target tab without this hint. Reload the development window and Ctrl+click a web link to check its placement and disappearance manually; accepted screenshots are unchanged.
